# ПРОМЕТ · Отгрузки Комус

Внутреннее веб-приложение для распределения продукции по паллетам, полным машинам и датам отгрузки. Календарь показывает количество машин на каждую дату; по нажатию открываются товарный состав, заказы, счета и схема размещения.

## Возможности

- Загрузка `.xlsx` со списком продукции: выбор конкретного листа, чтение заказа, счёта, количества, подтверждённой готовности, срока отгрузки и явно указанного фактически отгруженного количества.
- Загрузка справочника Тула: C — наименование, D — кратность, A — маркер и цвет, B — ВП.
- Редактирование товаров, количества, сроков и справочника в интерфейсе; поиск.
- Сборка строго по одной из 12 утверждённых схем; недогруженных машин в результате нет.
- Три варианта расчёта: приоритет сроков, количество паллет, баланс сроков и вместимости.
- Интерактивная схема паллет, календарь отгрузок, причины нераспределённого остатка.
- Excel с листами «Машины», «Расстановка», «Остаток», «Примечания»; печать / PDF средствами браузера.
- Общий проект на сервере в SQLite, защита от перезаписи при одновременном сохранении из двух вкладок.
- Вход по общему паролю, сессия на 12 часов, CSRF-проверка, ограничение попыток входа.
- Светлая и тёмная темы. Публичная демонстрация `/demo` использует только вымышленные данные; изменение реального проекта в ней недоступно.

## Правила расчёта

1. «Дата подтверждённая» — готовность завода; отправлять раньше нельзя. Пустые даты блокируют соответствующую строку, даты соседних строк не наследуются.
2. Количество для расчёта = количество в строке минус «Уже отгружено». Перед расчётом пользователь подтверждает сверку. Плановые колонки «Отгрузка …», зелёная заливка и архив **не считаются фактом** и автоматически не вычитаются. Если загружаются уже чистые остатки, «Уже отгружено» должно быть 0.
3. Наименования сопоставляются после нормализации регистра, пробелов, пунктуации и визуально сходных букв. При отсутствии или неоднозначности совпадения строка требует исправления; нечёткие совпадения автоматически не принимаются.
4. Красная 0,5 — одиночная финпаллета 1000 × 1200 мм; две рядом занимают ряд длиной 1000 мм. Чёрная 1 — неделимый сдвоенный паллет длиной 1200 мм по борту.
5. Красная 1 разделяется на две одиночные паллеты. Для числовой кратности указывается количество на сдвоенный паллет, затем делится пополам. Значение должно делиться на 2.
6. Сложные значения вида `22*2п`, `от 50 шт.` не трактуются автоматически: нужно указать подтверждённое количество на сдвоенный паллет и снять «Проверить» в справочнике.
7. ВП сохраняет требование вертикального паллетирования; размер места определяется маркером A. Маркер 0 не создаёт место, но требует указания способа размещения / крепления. Такой товар присоединяется только к существующей полной машине после наступления его готовности.
8. Разные товары и заказы не смешиваются на одном паллете. Партию можно разделять по машинам на границах получившихся паллет. Последняя неполная паллета занимает целое место, это отдельно отмечается.
9. Обычно одна машина в каждый будний день. Вторая возможна, если у оставшегося доступного груза просрочка относительно «Отгрузить до» **более 3 рабочих дней**. Не более двух машин в день.
10. Полная машина — ровно одна из 12 схем ниже. Рабочая длина кузова 13 500 мм. Исходная листовка построена для 13 400 мм; разрешённые комбинации сохранены без изменений.
11. Рабочие дни — пн–пт; календарь государственных праздников не подключён. Горизонт — 120 календарных дней от выбранного начала. Если полной машины собрать нельзя, остаток получает причину переноса / догруза.
12. Это план **расстановки по габаритам**. Вес, высота, грузоподъёмность, устойчивость и физическая совместимость крепления требуют проверки перед погрузкой. Алгоритм эвристический, глобальная оптимальность не гарантируется.

## Установка на существующий Linux-сервер

Требуются Git, Docker с Compose v2, Nginx с каталогами `sites-available` / `sites-enabled`, curl, ss, openssl. Установщик не обновляет другие приложения, не удаляет другие конфигурации, не меняет DNS и не устанавливает системные пакеты. Новый контейнер публикуется только на loopback. По умолчанию порт 8093; занятый порт останавливает установку.

Сначала создайте DNS A-запись выбранного поддомена на адрес сервера. Затем в терминале сервера:

```bash
sudo git clone https://github.com/egcherepita-rgb/komus.git /opt/komus
cd /opt/komus
sudo bash deploy/install.sh ВАШ_ДОМЕН 8093
```

`ВАШ_ДОМЕН` замените реальным доменом. Установщик проверяет конфликты домена, порта и Docker-проекта, сохраняет резервную копию Nginx в `/root/komus-install-backup.*`, создаёт случайный пароль в `.env`, собирает только Docker-проект `promet-komus`, проверяет `/health`, добавляет отдельный vhost Nginx, проверяет `nginx -t`, затем перечитывает конфигурацию. Если проверка Nginx не проходит, добавленный vhost удаляется; существующие файлы не меняются. Если конфигурация этого приложения уже существует, установщик откажется её перезаписывать. Повторный запуск после частичной установки выполняйте по ручному сценарию ниже, сохраняя `.env` и данные.

Пароль сохранён в `/opt/komus/.env` и не выводится установщиком. После включения HTTPS посмотрите его локально в терминале через `sudo nano /opt/komus/.env`; не присылайте содержимое файла или пароль в чат. До ввода пароля через сеть включите HTTPS. При установленном Certbot:

```bash
sudo certbot --nginx -d ВАШ_ДОМЕН
sudo nano /opt/komus/.env
```

В `.env` установите `COOKIE_SECURE=1`, затем:

```bash
cd /opt/komus
sudo docker compose up -d
```

Откройте `https://ВАШ_ДОМЕН`. Пароль не отправляйте в переписку и не добавляйте в Git.

### Ручной запуск контейнера

```bash
cp .env.example .env
# Отредактируйте .env: уникальный пароль не короче 12 символов, свободный порт.
chmod 600 .env
docker compose up -d --build
docker compose ps
curl -f http://127.0.0.1:8093/health
```

Затем подключите reverse proxy своего сервера к `http://127.0.0.1:8093`. Пример server block генерируется `deploy/install.sh`. Сохраните исходный Host через `proxy_set_header Host $host;`, разрешите загрузки до 16 МБ и таймаут обработки до 120 секунд. Для HTTPS установите `COOKIE_SECURE=1`.

### Обновление и данные

```bash
cd /opt/komus
sudo bash deploy/update.sh
```

Скрипт создаёт согласованную SQLite-копию в `backups/`, делает `git pull --ff-only` и пересобирает контейнер. Данные остаются в отдельном Docker volume `promet-komus_komus-data`. Не выполняйте `docker compose down -v`: это удаляет данные.

Восстановление резервной копии: остановите приложение; замените `/data/komus.db` содержимым выбранной копии через служебный контейнер с тем же volume, удалив старые WAL/SHM только при остановленном приложении; проверьте владельца UID 10001; запустите приложение и проверьте `/health` и вход. Перед восстановлением сделайте отдельную копию текущего volume.

Установка сохраняет один общий рабочий проект. Роли, персональные аккаунты, журнал фактических отгрузок и автоматическая синхронизация с заводом в эту версию не входят. Фактическую отгрузку вносите в исходные остатки или поле «Уже отгружено».

## Локальная разработка

Python 3.12+, браузер. Node.js нужен только при использовании команды `npm run dev`; сборки JavaScript и CDN-зависимостей нет.

```bash
python -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
# Задайте APP_PASSWORD через окружение, не записывайте секрет в команду Git.
python server.py
```

По умолчанию `127.0.0.1:8080`, локальные данные в `data/komus.db`. Можно задать `HOST`, `PORT`, `DATA_DIR`, `COOKIE_SECURE`. Для предпросмотра поддерживаются параметры `--host`, `--port`, `--strictPort`.

## Проверки

```bash
python -m unittest discover -s tests -v
node --check public/app.js
bash -n deploy/install.sh deploy/update.sh
```

21 автоматическая проверка: все 12 укладок; сохранение количества при разных стратегиях; недогруз; даты готовности и выходные; порог второй машины; неделимость чёрной 1; деление красной 1; отсутствие смешивания заказов; частично заполненные паллеты; товар без места; ошибки справочника; чтение Excel и безопасная выгрузка; вход, выход, CSRF, сохранение и конфликт версий. Интерфейс календаря, состав машины и карточка паллеты проверены в браузере на демонстрационных данных. Docker-сборка и работа на целевом сервере должны быть проверены при установке: в среде разработки Docker отсутствовал.

## Структура

- `planner.py` — алгоритм расстановки и 12 схем.
- `importer.py` — чтение Excel, цвет маркеров, экспорт.
- `server.py` — HTTP API, вход, сессии, SQLite.
- `public/` — интерфейс без внешних скриптов и сетевых шрифтов.
- `deploy/` — изолированная установка и обновление.

Логотип: официальный файл `https://www.safe.ru/local/templates/safe/img/logo2x.png`, сохранён локально в `public/assets/promet.png`. Права на логотип принадлежат правообладателю. `public/assets/layouts.svg` — исходная схема 12 укладок, предоставленная для проекта. Пользовательские книги Excel, заказы, пароли и рабочая база **не включены** в репозиторий; загрузите их через интерфейс после установки.
