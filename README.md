# ПРОМЕТ · Отгрузки Комус

Внутреннее веб-приложение для распределения продукции по паллетам, полным машинам и датам отгрузки. Версия 2 ведёт постоянный журнал заказов, подтверждённой готовности и фактических отгрузок. Главный экран — «Товар по машинам»; календарь показывает дату, количество машин и состав каждой.

## Возможности

- Однократная загрузка действующего файла отгрузок; сервер сохраняет журнал и исходные файлы.
- Постоянный справочник кратности Тула; загрузка только при изменениях. C — наименование, D — кратность, A — маркер и цвет, B — ВП.
- Два отдельных Excel-шаблона: новый заказ Комуса и ответ Донцовой. Один общий запрос Донцовой уже содержит все открытые заказы, товары и исходные количества.
- Предварительный просмотр перед применением: ошибки, совпадения, защита от повторной загрузки и перезаписи из другой вкладки.
- Независимый учёт одинакового товара в разных заказах, счетов, артикулов и даты готовности всей позиции.
- Сборка строго по одной из 12 утверждённых схем; недогруженных машин в результате нет.
- Три варианта расчёта: приоритет сроков, количество паллет, баланс сроков и вместимости.
- Отдельный раздел «Схемы укладки»: все 12 вариантов из алгоритма, количество одиночных / сдвоенных паллет, занятая и свободная длина. Переход к использованной схеме из карточки машины.
- Интерактивная схема паллет, календарь отгрузок, причины нераспределённого остатка.
- Excel с листами «Машины», «Расстановка», «Остаток», «Примечания»; печать / PDF средствами браузера.
- Отметка фактической отправки машины: списание остатков, неизменяемый состав в истории, автоматическая пересборка оставшегося плана.
- Общий журнал в SQLite с историей последних 20 версий и исходными загруженными книгами. Сохранение после каждого изменения.
- Вход по общему паролю, сессия на 12 часов, CSRF-проверка, ограничение попыток входа.
- Светлая и тёмная темы. Публичная демонстрация `/demo` использует только вымышленные данные; изменение реального проекта в ней недоступно.

## Как работать

| Что загружать | Куда | Когда |
|---|---|---|
| Действующий файл отгрузок | «Первоначальный файл» | Один раз при запуске |
| Справочник паллетизации | «Кратность Тула» | Первый раз и при изменениях |
| Новый заказ по шаблону | «Заказы Комуса» → «Загрузить новый заказ» | Каждый новый заказ |
| Готовность по заказу | «Ответы Донцовой» → «Загрузить ответ Донцовой» | После получения подтверждения / его изменения |

1. В первоначальной загрузке выберите нужный лист и смысл количества: полный заказ с явно указанным уже отгруженным или чистый неотгруженный остаток. Во втором случае учёт начинается с загруженного остатка, исторический полный объём не восстанавливается. Зелёная заливка и плановые колонки не означают факт отгрузки. Проверьте остатки, исправьте недостающие номера / сроки и подтвердите сверку на главном экране.
2. Загрузите кратность, проверьте неоднозначные записи в справочнике. Он сохраняется независимо от заказов.
3. Скачайте шаблон в «Заказы Комуса». В одном файле можно загрузить несколько новых заказов. В каждой строке укажите номер заказа, наименование, полное количество и «Отгрузить до». Счёт и артикулы заполняйте, если известны. Номер позиции не нужен. Существующие заказы защищены от повторного добавления.
4. Нажмите «Запрос по всем заказам»: приложение заполнит один Excel всеми неотгруженными товарами. Донцова указывает только дату готовности и дату ответа. Скачивание по выбранному заказу тоже доступно. Количество вручную не вводится: программа использует текущий остаток.
5. Загрузите ответ отдельной кнопкой. Новый ответ заменяет прежнюю дату готовности позиции. Если обе даты пустые, строка не меняется. Чтобы снять готовность, оставьте дату готовности пустой и заполните дату ответа. Одна позиция — одна строка; повторные строки блокируются.
6. Нажмите «Собрать машины». Программа использует сохранённые заказы, готовность, кратность и фактически отправленное количество. Результат сохраняется на сервере. После нового заказа, ответа или изменения кратности пересоберите машины. Планирование начинается не раньше текущего дня по Москве, даже если ранее была выбрана прошедшая дата.
7. Откройте машину или дату в календаре; нажмите паллету, чтобы увидеть заказ, счёт и дату готовности. Непоместившийся товар остаётся в разделе причин переноса.
8. Только после реальной отправки нажмите «Отметить отгруженной» на карточке машины. Остатки уменьшатся, машина попадёт в историю, оставшийся план пересоберётся с учётом уже использованных рейсов дня. Повторная отметка той же машины не списывает товар второй раз.

В обоих шаблонах нет номера позиции заказа. В ответе также нет частей, подтверждённого количества и комментария Донцовой. Исходное «Заказано, шт.» заполнено автоматически и помогает сопоставлению. Скрытый ID приложение проставляет само; вручную его вводить не нужно.

Ответ сопоставляется по номеру заказа или счёта и артикулу / наименованию товара. При повторяющихся товарах уточняются счёт и исходное количество. Без скрытого ID файл принимается при однозначном совпадении. Если совпадений несколько, загрузка блокируется с понятной причиной. Само количество не определяет товар. Более ранняя дата ответа не заменяет уже сохранённый ответ. Отправленное количество не возвращается в готовность: дата применяется только к текущему неотгруженному остатку.

Ручная коррекция количества сбрасывает готовность позиции: после неё нужен свежий ответ по остатку и повторная сверка. После первой фактической отгрузки реквизиты этой позиции и отгруженное количество защищены от ручной перезаписи.

Приложение не подключается к почте, 1С и заводу автоматически: входящие заказы / ответы загружает пользователь, факт отправки подтверждает пользователь. Данные после выхода и перезапуска сохраняются.

## Правила расчёта

1. «Дата подтверждённая» — готовность завода; отправлять раньше нельзя. Пустые даты блокируют соответствующую строку, даты соседних строк не наследуются.
2. Количество для расчёта = количество в строке минус «Уже отгружено». Перед расчётом пользователь подтверждает сверку. Плановые колонки «Отгрузка …», зелёная заливка и архив **не считаются фактом** и автоматически не вычитаются. Если загружаются уже чистые остатки, «Уже отгружено» должно быть 0.
3. Кратность сопоставляется по артикулам. Если таблица Тула не содержит артикулов, проверяется полное наименование без префикса `0MX_`. Для шкафов, сейфов, картотек и антресолей также допускается единственное совпадение по полному коду модели. Учитываются категория товара, вариант замка, «Стандарт» и «усиленный», марка «Комус Мебель», цвет и указанные с обеих сторон размеры или число секций. Для стеллажей сверяются серия, три размера и число полок. Сантиметры приводятся к миллиметрам, порядок размеров может отличаться. Если единицы не указаны, размерный ряд до 300 включительно читается как сантиметры, более крупный — как миллиметры. Суффиксы `/4` и `\4` означают четыре полки. Неоднозначные строки требуют проверки.
4. Красная 0,5 — одиночная финпаллета 1000 × 1200 мм; две рядом занимают ряд длиной 1000 мм. Чёрная 1 — неделимый сдвоенный паллет длиной 1200 мм по борту.
5. Красная 1 разделяется на две одиночные паллеты. Для числовой кратности указывается количество на сдвоенный паллет, затем делится пополам. Значение должно делиться на 2.
6. Сложные значения вида `22*2п`, `от 50 шт.` не трактуются автоматически: нужно указать подтверждённое количество на сдвоенный паллет и снять «Проверить» в справочнике.
7. ВП сохраняет требование вертикального паллетирования; размер места определяется маркером A. Маркер 0 не создаёт отдельное место, но требует указания способа размещения / крепления и положительной подтверждённой кратности отгрузки. Такой товар присоединяется только к существующей полной машине после наступления его готовности.
8. Разные товары и позиции заказов не смешиваются на одном паллете. Отгрузка всегда кратна целой паллете по справочнику. Один заказ можно разделять между машинами и днями только на границах паллет. Количество, которого не хватает до полной паллеты, остаётся с причиной. Одна дата готовности относится ко всему остатку позиции; паллеты этой позиции могут отгружаться в разные дни. Для красной 1 целая отгрузочная паллета — одна из двух одиночных, числовая кратность делится пополам.
9. Обычно одна машина в каждый будний день. Вторая возможна, если у оставшегося доступного груза просрочка относительно «Отгрузить до» **более 3 рабочих дней**. Не более двух машин в день.
10. Полная машина — ровно одна из 12 схем ниже. Рабочая длина кузова 13 500 мм. Исходная листовка построена для 13 400 мм; разрешённые комбинации сохранены без изменений.
11. Рабочие дни — пн–пт; календарь государственных праздников не подключён. Горизонт — 120 календарных дней от выбранного начала. Если полной машины собрать нельзя, остаток получает причину переноса / догруза.
12. Это план **расстановки по габаритам**. Вес, высота, грузоподъёмность, устойчивость и физическая совместимость крепления требуют проверки перед погрузкой. Алгоритм эвристический, глобальная оптимальность не гарантируется.

## Установка на существующий Linux-сервер

Требуются Git, Docker с Compose v2, Nginx с каталогами `sites-available` / `sites-enabled`, curl, ss, openssl. Установщик не обновляет другие приложения, не удаляет другие конфигурации, не меняет DNS и не устанавливает системные пакеты. Новый контейнер публикуется только на loopback. По умолчанию порт 8093; занятый порт останавливает установку.

Сначала создайте DNS A-запись выбранного поддомена на адрес сервера. Затем в терминале сервера:

```bash
sudo git clone https://github.com/egcherepita-rgb/komus.git /opt/komus
cd /opt/komus
sudo bash deploy/install.sh ВАШ_ДОМЕН 8093
```

`ВАШ_ДОМЕН` замените реальным доменом. Установщик проверяет конфликты домена, порта и Docker-проекта, сохраняет резервную копию Nginx в `/root/komus-install-backup.*`, создаёт случайный пароль в `.env`, собирает только Docker-проект `promet-komus`, проверяет `/health`, добавляет отдельный vhost Nginx, проверяет `nginx -t`, затем перечитывает конфигурацию. Если проверка Nginx не проходит, добавленный vhost удаляется; существующие файлы не меняются. Если конфигурация этого приложения уже существует, установщик откажется её перезаписывать. Повторный запуск после частичной установки выполняйте по ручному сценарию ниже, сохраняя `.env` и данные.

Пароль сохранён в `/opt/komus/.env` и не выводится установщиком. После включения HTTPS посмотрите его локально в терминале через `sudo nano /opt/komus/.env`; не присылайте содержимое файла или пароль в чат. До ввода пароля через сеть включите HTTPS. При установленном Certbot:

```bash
sudo certbot --nginx -d ВАШ_ДОМЕН
sudo nano /opt/komus/.env
```

В `.env` установите `COOKIE_SECURE=1`, затем:

```bash
cd /opt/komus
sudo docker compose up -d
```

Откройте `https://ВАШ_ДОМЕН`. Пароль не отправляйте в переписку и не добавляйте в Git.

### Ручной запуск контейнера

```bash
cp .env.example .env
# Отредактируйте .env: уникальный пароль не короче 12 символов, свободный порт.
chmod 600 .env
docker compose up -d --build
docker compose ps
curl -f http://127.0.0.1:8093/health
```

Затем подключите reverse proxy своего сервера к `http://127.0.0.1:8093`. Пример server block генерируется `deploy/install.sh`. Сохраните исходный Host через `proxy_set_header Host $host;`, разрешите загрузки до 16 МБ и таймаут обработки до 120 секунд. Для HTTPS установите `COOKIE_SECURE=1`.

### Обновление и данные

```bash
cd /opt/komus
sudo bash deploy/update.sh
```

Скрипт создаёт согласованную SQLite-копию в `backups/`, делает `git pull --ff-only` и пересобирает контейнер. Данные остаются в отдельном Docker volume `promet-komus_komus-data`. Не выполняйте `docker compose down -v`: это удаляет данные.

Восстановление резервной копии: остановите приложение; замените `/data/komus.db` содержимым выбранной копии через служебный контейнер с тем же volume, удалив старые WAL/SHM только при остановленном приложении; проверьте владельца UID 10001; запустите приложение и проверьте `/health` и вход. Перед восстановлением сделайте отдельную копию текущего volume.

Обновление версии 1 переводит сохранённый проект в журнал версии 2 без удаления заказов и кратности. Исходное JSON-состояние сохраняется в истории базы; исходные Excel прошлой версии восстановить нельзя, если они ранее не сохранялись. Для старых строк без номера позиции создаются постоянные внутренние номера. План после миграции нужно собрать заново. После включения правила целых паллет и одной даты готовности позиции также требуется пересборка: старые планы нельзя экспортировать или отмечать отгруженными. Сохранённая история фактических отправок не меняется. Роли, персональные аккаунты и автоматическая синхронизация с заводом не подключены.

## Локальная разработка

Python 3.12+, браузер. Node.js нужен только при использовании команды `npm run dev`; сборки JavaScript и CDN-зависимостей нет.

```bash
python -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
# Задайте APP_PASSWORD через окружение, не записывайте секрет в команду Git.
python server.py
```

По умолчанию `127.0.0.1:8080`, локальные данные в `data/komus.db`. Можно задать `HOST`, `PORT`, `DATA_DIR`, `COOKIE_SECURE`. Для предпросмотра поддерживаются параметры `--host`, `--port`, `--strictPort`.

## Проверки

```bash
python -m unittest discover -s tests -v
node --check public/app.js
node --test tests/test_upload_ui.cjs
bash -n deploy/install.sh deploy/update.sh
```

Автоматические проверки покрывают 12 укладок, сохранение количества, недогруз, даты готовности и выходные, порог второй машины, типы паллет, сопоставление заказов, одну дату готовности всей позиции, повторные / устаревшие ответы, первоначальный импорт, миграцию старой базы, фактические отправки и пересборку, транзакции, вход, CSRF и конфликт версий. Интерфейс календаря, состав машины, карточка паллеты и раздельные заказы проверены в браузере на демонстрационных данных. Docker-сборка и работа на целевом сервере проверяются при обновлении.

## Структура

- `planner.py` — алгоритм расстановки и 12 схем.
- `importer.py` — чтение Excel, цвет маркеров, экспорт.
- `import_v2.py` — первоначальная загрузка, два шаблона, проверка заказов и ответов.
- `workflow.py` — журнал заказов, дату готовности позиции, списание и пересборка машин.
- `ledger_store.py` — SQLite, миграция, версии, исходные файлы и транзакции.
- `server.py` — HTTP API, вход и сессии.
- `public/` — интерфейс без внешних скриптов и сетевых шрифтов.
- `deploy/` — изолированная установка и обновление.

Логотип: официальный файл `https://www.safe.ru/local/templates/safe/img/logo2x.png`, сохранён локально в `public/assets/promet.png`. Права на логотип принадлежат правообладателю. `public/assets/layouts.svg` — исходная схема 12 укладок, предоставленная для проекта. Пользовательские книги Excel, заказы, пароли и рабочая база **не включены** в репозиторий; загрузите их через интерфейс после установки.
